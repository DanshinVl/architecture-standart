# ADR — Распространение ставок депозитов в кол-центры

## Название задачи
Передача актуальных ставок депозитов в систему кол-центра банка и партнёрский кол-центр

## Автор
Владислав Даньшин

## Дата
2026

---

# Контекст

В текущем процессе ставки по депозитам рассчитываются и хранятся в Excel-файлах.

Сотрудники бэк-офиса депозитов и кредитов согласуют специальные ставки вручную.  
После согласования информация передается в отделения и кол-центр.

При этом:

- операторы кол-центра должны иметь доступ к актуальным ставкам
- партнёрский кол-центр также должен получать актуальные ставки
- партнёрский кол-центр может получать данные **только в виде файлов**
- API или интеграция через SFTP недоступны

Необходимо реализовать механизм централизованного управления ставками и их передачи:

- во внутреннюю систему кол-центра
- во внешний партнёрский кол-центр

# Нефункциональные требования

| № | Требование                                                                       |
|:-:|:---------------------------------------------------------------------------------|
| 1 | Система должна хранить актуальные ставки в централизованной базе данных          |
| 2 | Изменения ставок должны быть доступны системам банка в течение короткого времени |
| 3 | Система должна поддерживать аудит изменений ставок                               |
| 4 | Передача файла партнёрскому кол-центру должна выполняться регулярно              |
| 5 | Архитектура должна поддерживать расширение на другие банковские продукты         |
| 6 | Решение должно быть устойчивым к сбоям интеграции                                |
| 7 | Система должна поддерживать мониторинг и логирование                             |

# Решение

Предлагается внедрить отдельный сервис управления депозитными ставками — **Rate Management Service**.

Этот сервис станет централизованным источником ставок и будет выполнять следующие функции:

- хранение ставок депозитных продуктов
- управление изменениями ставок
- предоставление ставок внутренним системам банка через API
- формирование файла ставок для партнёрского кол-центра

---

## Основные компоненты решения

**Rate Management Service**

Отвечает за:

- хранение ставок
- управление изменениями ставок
- предоставление ставок другим системам

---

**Система кол-центра банка**

Получает ставки через API и использует их при консультации клиентов.

---

**File Export Service**

Формирует файл со ставками для партнёрского кол-центра.

---

**Партнёрский кол-центр**

Получает файл со ставками и использует его в своей системе.

# Альтернативы

## Использование Excel как основного источника ставок

В этом варианте ставки продолжают храниться в Excel.

Недостатки:

- высокая вероятность ошибок
- отсутствие централизованного хранения
- сложность интеграции с системами банка
- отсутствие аудита изменений

---

## Хранение ставок непосредственно в АБС

В этом варианте ставки управляются через АБС.

Недостатки:

- сложность изменений в АБС
- высокая стоимость разработки
- низкая гибкость архитектуры

---

# Недостатки, ограничения, риски

## Ограничения

- партнёрский кол-центр может принимать данные только в формате файлов
- необходимо использовать существующую систему кол-центра

## Риски

- задержки передачи файла партнёрскому кол-центру
- необходимость синхронизации ставок между системами
- возможные ошибки при ручной обработке файла партнёром

## Недостатки решения

- требуется внедрение нового сервиса
- требуется поддержка дополнительной инфраструктуры
