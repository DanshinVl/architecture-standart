# Контекст

В текущем состоянии открытие депозитов выполняется преимущественно через отделения банка.  
Часть процессов выполняется вручную:

- расчёт ставок ведётся в Excel
- взаимодействие между подразделениями выполняется через email
- интернет-банк не поддерживает открытие депозитов

При этом банк стремится начать цифровизацию депозитных продуктов.

В рамках MVP необходимо реализовать возможность подачи заявки на депозит:

- через сайт (для новых клиентов)
- через интернет-банк (для действующих клиентов)

При этом:

- расчёт ставок может выполняться автоматически
- обработка заявки остаётся за сотрудниками бэк-офиса
- АБС остаётся основной системой учёта депозитных договоров

# Нефункциональные требования

| № | Требование                                                              |
|:-:|:------------------------------------------------------------------------|
| 1 | Система должна обеспечивать сохранность данных заявок                   |
| 2 | Архитектура должна поддерживать масштабирование при росте пользователей |
| 3 | Время регистрации заявки не должно превышать нескольких секунд          |
| 4 | Система должна обеспечивать аудит операций                              |
| 5 | Система должна поддерживать повторную обработку заявки при сбое         |
| 6 | Архитектура должна позволять добавлять новые депозитные продукты        |
| 7 | Решение должно поддерживать мониторинг и логирование                    |
| 8 | АБС остаётся основной системой учёта депозитов                          |

# Решение

Для реализации MVP предлагается использовать отдельный сервис обработки депозитных заявок.

Основные компоненты решения:

- **Сайт банка** — позволяет новому клиенту подать заявку
- **Интернет-банк** — позволяет действующему клиенту открыть депозит
- **Deposit MVP Service** — новый сервис обработки заявок
- **Система кол-центра** — используется для сопровождения заявок новых клиентов
- **АБС** — основная банковская система учёта депозитов
- **SMS-шлюз** — отправка кодов и уведомлений

Основные принципы архитектуры:

- пользовательские каналы (сайт, интернет-банк) отделены от бизнес-логики
- новая функциональность не реализуется напрямую в АБС
- АБС используется как система учёта
- MVP-сервис управляет жизненным циклом заявки

### Контейнерная диаграмма

Контейнерная диаграмма детализирует архитектуру системы.

Детализированы следующие системы:

**Интернет-банк**

Разделён на:

- Web UI
- Application Layer
- Database

Интернет-банк принимает действия пользователя, вызывает сервис MVP и выполняет подтверждение операции через SMS.

---

**MVP система депозитов**

Включает:

- API слой (Channel API)
- сервис обработки заявок
- сервис ставок
- сервис уведомлений
- базу данных заявок

Этот слой реализует основную бизнес-логику MVP.

---

**АБС**

Включает:

- клиентское приложение сотрудника
- интеграционный слой
- модуль обработки депозитов
- модуль управления договорами
- базу данных Oracle

АБС выполняет:

- обработку заявки
- создание депозитного договора
- отправку SMS уведомлений

# Альтернативы

## Реализация функциональности напрямую в АБС

В этом варианте логика открытия депозитов реализуется внутри АБС.

Недостатки:

- высокая стоимость изменения АБС
- риск нарушения существующих процессов
- низкая гибкость архитектуры

---

## Реализация логики в интернет-банке

В этом варианте вся логика реализуется в интернет-банке.

Недостатки:

- усложнение интернет-банка
- отсутствие разделения ответственности
- сложность масштабирования

---

# Недостатки, ограничения, риски

## Ограничения

- АБС остаётся основной системой учёта депозитов
- необходимо использовать существующий SMS-шлюз
- интеграция должна учитывать систему кол-центра

## Риски

- возможные задержки интеграции с АБС
- нагрузка на интернет-банк при росте пользователей
- необходимость синхронизации данных между системами

## Недостатки решения

- появляется дополнительный сервис
- требуется новая инфраструктура для его эксплуатации
